# 📌 Contributing to LAB.LOCAL

*Fast & Secure by Design.*

Thank you for your interest in contributing! This project is primarily a personal portfolio, but improvements, corrections, and suggestions are always welcome. Whether it's a documentation fix, a better script, or a new diagram, every contribution helps make the LAB.LOCAL ecosystem a more valuable resource.

> **Note:** All code, documentation, and assets related to the infrastructure live in the 
> [`infrastructure`](https://github.com/lab-local/infrastructure) repository. 
> If you're looking to contribute to the infrastructure or scripts, please start there.

## How to contribute

1. **Fork the repository** and create a branch for your change.
2. **Make your changes** (see the style guidelines below).
3. **Commit with a clear message** (e.g., "fix: correct typo in network-design.md").
4. **Open a pull request** and describe your change in the description.

You can also open an **issue** to suggest improvements, report errors, or discuss ideas.

## What we’re looking for

- **Documentation improvements** – Clearer explanations, better structure, or additional details in the `docs/` folder.
- **Script enhancements** – Optimizations, bug fixes, or new automation scripts in `automation-scripts/`.
- **Infrastructure as Code improvements** – Better OpenTofu or Ansible configurations.
- **Diagram updates** – Corrections or new diagrams in `diagrams/` or `docs/`.
- **Grammar and spelling fixes** – In the README or documentation files.

## Style guidelines

- For documentation, use **Markdown** and keep the tone **clear and professional**.
- For code (scripts, IaC), follow the existing style and conventions.
- Use **descriptive commit messages** (e.g., "fix: correct IP range in VPN config").
- If you add a new feature, please update the relevant documentation.

## Review process

All contributions will be reviewed by the maintainer. We aim to respond within a reasonable timeframe. Contributions may be accepted, revised, or discussed further.

## Before opening a pull request

If your change is substantial, please open an issue first to discuss the direction. This avoids wasted effort and ensures the change aligns with the project's vision.

## Thank you

Every contribution, no matter how small, helps make LAB.LOCAL better for everyone. We're grateful for your time and effort.
